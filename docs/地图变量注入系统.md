# 地图变量注入系统 · 完整方案

> 基于 GAME-DESIGN.md 的位置系统设计，本文档描述地图变量如何被过滤、格式化并注入到 AI 提示词中。

---

## 一、总览

地图数据存储在变量 `stat_data.地图` 中，是一个树形结构。系统在组装提示词时，扫描世界书文本中的 `{{MAP}}` 宏，将其替换为**经过过滤处理的地图文本**。

过滤规则由三个因素共同决定：

- **当前位置**（字符串，如 `'601室'`）
- **是否位于梦境**（布尔值，`stat_data.世界.梦境定位.位于梦境`）
- **节点与当前位置在树中的路径关系**

---

## 二、数据结构

### 2.1 节点标准格式（不变）

```
节点名: {
  检索词: ['关键词1', '关键词2'],
  方位: { X: [min, max], Y: [min, max], Z: [min, max] },
  现实: {
    描述: '...',
    地点细节: {
      信息: ['信息条目1', '信息条目2'],
      异常: {
        异常名: { 评级, 描述, 具现进度, ... }
      }
    }
  },
  梦境: {
    描述: '...',
    地点细节: {
      信息: ['...'],
      异常: { ... }
    }
  },
  子地图: { ... }
}
```

### 2.2 位置变量（不变，纯字符串）

```
世界.现实.地点: '601室'
世界.梦境定位.位于梦境: false
```

---

## 三、`{{MAP}}` 宏机制

### 3.1 标记格式

世界书作者在任意位置插入：

```
{{MAP}}
```

共 7 个字符（含两侧花括号），整体替换。

### 3.2 替换流程

```
世界书文本（含 {{MAP}}）
  ↓
提示词组装器扫描文本，发现 {{MAP}}
  ↓
调用地图处理器：
  输入：当前位置（字符串）、是否位于梦境（布尔）、完整地图树
  输出：过滤后的地图文本
  ↓
用输出的地图文本替换 {{MAP}}
  ↓
继续后续组装（角色卡等）
```

### 3.3 边界行为

| 情况 | 处理方式 |
|------|---------|
| 世界书中没有 `{{MAP}}` | 不注入，不报错 |
| 世界书中有多个 `{{MAP}}` | 每个都被替换为同样的地图文本（建议只放一个） |
| 地图树为空或不存在 | `{{MAP}}` 替换为空字符串 |

## 四、地图处理器核心算法

### 步骤一：定位当前位置（resolvePath）

用当前位置的字符串值（如 `'601室'`）在地图树中搜索匹配的节点。

**匹配规则**（按优先级）：

1. 节点的**键名**与当前位置字符串精确相等（如键名 `'601室'` 直接命中）
2. 节点的**检索词数组**包含该字符串
3. 节点的键名或检索词与当前位置字符串**互相包含**（兜底模糊匹配）

从根到命中节点，构建**路径数组**：

```
[蓝星, 东煌区, 夏城, 锦荣区, 幸福小区, 11号楼, 601室]
```

若搜索不到（当前位置字符串不匹配任何节点），返回**整棵树的简化版**：所有节点仅显示方位和描述，不展开任何子地图。

### 步骤二：世界层过滤

根据 `位于梦境` 的真假值，对整棵树做字段剥离：

**位于梦境 = false（在现实）**：
- 每个节点保留 `现实` 字段及其全部内容
- 每个节点删除 `梦境` 字段
- 若某节点 `现实` 字段为空，该节点显示为空壳（仅名称）

**位于梦境 = true（在梦中）**：
- 每个节点保留 `梦境` 字段及其全部内容
- 每个节点删除 `现实` 字段
- **额外保留**：每个节点同时保留 `现实.描述`，作为 `现实原型` 字段输出，让 AI 知道梦境场景对应的现实参照物
- 若某节点 `现实.描述` 为空，则不输出 `现实原型`

这一步在距离判断之前完成。后续所有过滤只操作剥离后剩下的数据。

### 步骤三：按节点关系逐层过滤

从根节点开始，递归遍历整棵树。对每个节点，归入以下四类之一：

#### 类型 A：当前节点（路径末端）

**判定**：节点的路径数组与当前位置路径完全相同。

**输出**：
- 方位 ✓
- 描述 ✓
- 地点细节 → **完整**（信息数组全部 + 异常对象完整字段）
- 子地图 → **仅展开一层**。遍历直属子节点，每个子节点应用步骤三判定类型。子节点的子地图不再展开（无论判定为何种类型）。

#### 类型 B：兄弟节点（同父、不同自身）

**判定**：与当前节点共享同一个父节点，但自身不是当前节点。即路径前 n-1 段完全相同，仅最后一段不同。

**输出**：
- 方位 ✓
- 描述 ✓
- 地点细节 → **完整**（与类型 A 相同的信息密度）
- 子地图 → **不展开**

#### 类型 C：路径祖先节点（路径前缀）

**判定**：节点路径是当前位置路径的**真前缀**。例如路径为 `[蓝星, 东煌区, 夏城, 锦荣区, 幸福小区, 11号楼, 601室]`，则 `蓝星`、`东煌区`、`夏城`、`锦荣区`、`幸福小区`、`11号楼` 都是路径祖先。

**输出**：
- 方位 ✓
- 描述 ✓
- 地点细节 → **仅直接父级**（`pathIndex === path.length - 1`）输出，与类型 B 一致（信息数组全部 + 异常：评级+描述，无具现进度）。更远的祖先节点不输出地点细节。
- 子地图 → **展开**，遍历子节点并对每个子节点应用步骤三

#### 类型 D：旁系节点（其他所有）

**判定**：不满足以上任何一种。既不是当前节点、不是兄弟、也不在路径上。

**输出**：
- 方位 ✓
- 描述 ✓
- 地点细节 → **不输出**
- 子地图 → **不展开**

### 步骤四：异界特殊规则（覆盖类型 D）

当遍历到**异界节点的直接子节点**时，覆盖类型 D 的"不展开子地图"规则：

- 异界本身的子地图**展开一层**：直属子节点（如 太虚界、蛊界、鬼蜮）各输出方位+描述
- 这些直属子节点的子地图**不再展开**
- 如果异界位于路径上（即玩家身处异界之中），则按类型 A/C 正常展开，不需要此特殊规则

### 步骤五：格式化输出

将过滤后的树转换为缩进文本。输出格式为类 YAML：

```
节点名:
  方位: X:[min, max] Y:[min, max] Z:[min, max]
  描述: 文本内容
  现实原型: 文本内容          ← 仅位于梦境=true时出现
  地点细节:                   ← 类型 A/B/C
    信息:
      - 信息条目1
      - 信息条目2
    异常:
      异常名:
        评级: S/A/B/C
        描述: ...
        具现进度: ...%        ← 仅类型 A；类型 B 不输出此字段
  子地图:                     ← 仅类型 A/C + 异界特殊
    子节点名:
      ...
```

## 五、信息密度总表

| | 类型 A（当前） | 类型 B（兄弟） | 类型 C（路径祖先） | 类型 D（旁系） | 异界第一层 |
|---|---|---|---|---|---|
| **方位** | ✓ | ✓ | ✓ | ✓ | ✓ |
| **描述** | ✓ | ✓ | ✓ | ✓ | ✓ |
| **现实原型**（梦境时） | ✓ | ✓ | ✓ | ✓ | ✓ |
| **地点细节·信息** | ✓ | ✓ | 仅直接父级 | — | — |
| **地点细节·异常** | ✓（完整含具现进度） | ✓（评级+描述，无具现进度） | 仅直接父级（评级+描述，无具现进度） | — | — |
| **子地图** | 仅一层 | — | 展开（穿透路径） | — | 仅一层 |

## 八、架构与集成点

```
stat_data.地图（变量树）
      │
      ▼
地图处理器（纯函数，TypeScript）
  · resolvePath(currentLocation, mapTree)  → 路径数组 | null
  · filterMap(mapTree, path, isDream)      → 过滤后的地图树
  · formatMap(filteredTree)                → 缩进文本字符串
      │
      ▼
prompt-assembler.ts
  · 加载世界书文本
  · 扫描 {{MAP}}
  · 调用地图处理器
  · 替换文本
  · 继续组装
      │
      ▼
发送给 AI 的完整提示词
```

### 三个核心函数

| 函数 | 输入 | 输出 | 职责 |
|------|------|------|------|
| `resolvePath` | 位置字符串 + 完整地图树 | 路径数组或 `null` | 在树中按 键名/检索词 搜索，构建路径 |
| `filterMap` | 树 + 路径 + isDream | 过滤后的地图树对象 | 应用世界层过滤 + 四类节点规则 + 异界特殊规则 |
| `formatMap` | 过滤后的地图树 | 缩进文本 | 转为 AI 可直接读取的类 YAML 文本 |

### 修改文件清单

| 文件 | 改动内容 | 代码量 |
|------|---------|--------|
| `variables.ts` | 新增 `resolvePath()` 函数 | ~40 行 |
| `map-filter.ts`（新文件） | 新增 `filterMap()` + `formatMap()` | ~120 行 |
| `prompt-assembler.ts` | 扫描 `{{MAP}}` → 调用处理器 → 替换 | ~15 行 |

## 九、注意事项

### 9.1 `formatMap` 的 isMetaKey 误用

`MAP_META_KEYS = ['检索词', '方位', '现实', '梦境', '子地图']` 用于**输入树**（原始地图数据）的遍历，跳过节点结构属性以获取地点条目。

`formatMap` 操作的是**过滤后的输出树**，其中 `方位`、`子地图` 等已是合法的内容字段。如果在 `formatMap` 中也用 `isMetaKey` 过滤键名，会导致 `方位` 和 `子地图` 被错误丢弃，输出只剩 `描述`。

**教训**：输入树的元数据键和输出树的内容键是两类不同的键集合，不能共用一个过滤函数。

## 十、边界情况

| 情况 | 处理方式 |
|------|---------|
| 世界书中没有 `{{MAP}}` | 不注入，不报错 |
| 当前位置匹配不到任何节点 | 返回整棵树简化版（所有节点仅方位+描述） |
| 当前位置匹配到多个节点（同名检索词） | 后续引入消歧优先级（GAME-DESIGN §1.5） |
| 地图树为空或不存在 | `{{MAP}}` 替换为空字符串 |
| 节点只有「现实」没有「梦境」字段 | 梦境模式下该节点仅显示 `现实原型`，其余为空壳 |
| 节点没有「方位」或「描述」 | 该字段省略不输出 |
| 梦境模式下，节点的 `现实.描述` 为空 | 不输出 `现实原型` 行 |
| 路径非常深（如 10 层以上） | 不影响算法，祖先逐层展开，旁系仅一行 |
| 当前节点有子地图（如 601室 下有 客厅/卧室） | 仅展开一层直属子节点，不再深入（类型 A 规则） |

## 十一、后续扩展预留

此方案为以下 GAME-DESIGN 功能预留了接口：

| 功能 | 预留点 |
|------|--------|
| **多人共处检测** | 地图处理器可扩展为接受多个位置参数，输出"同在场景"NPC 清单 |
| **距离/时间估算** | 方位数据已在输出中，后续可追加距离字段而无需改数据结构 |
| **双世界切换** | `filterMap` 已处理现实/梦境剥离，切换输入参数即可获得另一世界视图 |
| **世界地点自动跟随** | `resolvePath` 可供 `vars-merger` 调用，验证位置变更合法性 |
| **消歧优先级** | `resolvePath` 可接受第二参数（当前路径），实现从近到远搜索 |
| **坐标计算** | 方位范围天然可求中点、算距离、判断包含关系 |
