## 一、后端：数据采集层

### 1.1 采集策略

不 monkey-patch 全局 `fetch`，而是在现有 `sendGameMessage` 里嵌入采集逻辑。

**第一 API（流式）**：SSE 流的最后一条 chunk 携带 `usage` 字段。当前代码只提取了 `delta.content`，需要同时捕获 `usage`。

```
当前:
  data: {"choices":[{"delta":{"content":"..."}}]}
  data: [DONE]

实际上 DeepSeek 返回:
  data: {"choices":[{"delta":{"content":"..."}}]}
  data: {"choices":[{"delta":{},"usage":{"prompt_cache_hit_tokens":8000,"prompt_cache_miss_tokens":2000,...}}]}
  data: [DONE]
```

**采集点**：`useSillytavern.ts` 的 SSE 解析循环中，保存最后一个 chunk 的 `usage` 字段。

**第二 API（非流式）**：直接读 `response.json().usage`。当前代码已经做了一次 `response.json()`，再加一行提取 `d.usage`。

### 1.2 数据模型

```typescript
// types.ts 新增

interface CacheUsageRecord {
  /** 请求唯一 ID */
  requestId: string;
  /** 时间戳 */
  timestamp: number;
  /** 使用的 API: primary / secondary */
  apiTarget: 'primary' | 'secondary';
  /** 使用的模型名 */
  model: string;
  /** 当前聊天 ID */
  chatId: string;
  /** 缓存命中 tokens */
  hit: number;
  /** 缓存未命中 tokens */
  miss: number;
  /** 总 prompt tokens */
  total: number;
  /** 命中率 0-100 */
  hitRate: number;
  /** 估算费用（元） */
  cost: number;
  /** 生成 tokens（completion_tokens） */
  generated: number;
}
```

### 1.3 存储

在项目已有的 IndexedDB 中新增 `cacheUsage` 表（Dexie schema 升级）：

```typescript
// database.ts — add to schema
db.version(2).stores({
  settings: 'key',
  chats: 'id',
  cacheUsage: 'requestId',  // 新增
});
```

### 1.4 计费模型

```typescript
// cache-monitor.ts

const PRICING = {
  'deepseek-chat':      { name: 'V4 Flash', hit: 0.02, miss: 1.00 },
  'deepseek-reasoner':  { name: 'V4 Pro',   hit: 0.025, miss: 3.00 },
  // 可通过设置页扩展
  'default':            { name: '未知模型',  hit: 0.02, miss: 1.00 },
};

function calculateCost(model: string, hit: number, miss: number): number {
  const pricing = PRICING[model] ?? PRICING['default'];
  return (hit / 1_000_000) * pricing.hit + (miss / 1_000_000) * pricing.miss;
}
```

### 1.5 事件总线集成

```typescript
// 在 sendGameMessage 中，API 调用完成后
gameBus.emit('api_usage', {
  requestId: crypto.randomUUID(),
  timestamp: Date.now(),
  apiTarget: 'primary',
  model: effectiveApi.model,
  chatId: effectiveChat.id,
  hit: usage?.prompt_cache_hit_tokens ?? 0,
  miss: usage?.prompt_cache_miss_tokens ?? 0,
  total: (usage?.prompt_cache_hit_tokens ?? 0) + (usage?.prompt_cache_miss_tokens ?? 0),
  generated: usage?.completion_tokens ?? 0,
} as CacheUsageRecord);

// 异步写入 IndexedDB，不阻塞主流程
saveUsageRecord(record);
```

### 2.5 命中率条设计

用 `motion/react` 做宽度动画的进度条：

```tsx
// 命中率条 — 渐变色根据命中率动态变化
<motion.div
  className="h-1 rounded-full"
  style={{
    background: hitRate >= 60 
      ? 'linear-gradient(90deg, #34d399, #00f2ff)' 
      : hitRate >= 30 
        ? 'linear-gradient(90deg, #f0a43c, #34d399)' 
        : 'linear-gradient(90deg, #ef4444, #f0a43c)',
  }}
  initial={{ width: 0 }}
  animate={{ width: `${hitRate}%` }}
  transition={{ duration: 0.6, ease: 'easeOut' }}
/>
```

### 2.6 差异对比面板

选中两条记录后，在面板底部展开差异对比：

```
┌──────────────────────────────────┐
│ ⚖️ 差异对比  #3 ← → #5      [✕] │
├──────────────────────────────────┤
│ #0 system — 内容一致              │
│                                  │
│ #1 user                           │
│  …湖边调查…                       │
│  …湖边调查… [青瞳封印松动]         │ ← 新增内容高亮
│                                  │
│ #2 assistant — 内容一致           │
└──────────────────────────────────┘
```

复用原插件的逐字 diff 算法（找前后公共前缀/后缀），用项目的颜色体系：
- 删除内容 → `aether-red` 背景 + 删除线
- 新增内容 → `aether-green` 背景 + 粗体
- 不变内容 → 灰色半透明

### 2.7 动画细节

| 场景 | 动画 |
|------|------|
| 面板打开 | `motion.div` scale 0.9→1 + opacity + blur(4px)→0，复用 SystemSettingsModal 的过渡 |
| 新记录插入 | 从上方滑入（`initial={{ y: -20, opacity: 0 }}`） |
| 命中率条 | 宽度从 0 动画到目标值 |
| 气泡脉冲 | 有新数据时触发 `animate-ping` 外圈 |
| 费用变化 | 数字翻滚效果（可选） |

## 五、实施顺序

| 步骤 | 内容 | 可独立验证 |
|------|------|-----------|
| **Step 1** | `cache-monitor.ts` + types + database | 控制台打印 usage 数据 |
| **Step 2** | `sendGameMessage` 中捕获 usage + emit 事件 | gameBus 能收到 `api_usage` |
| **Step 3** | `CacheMonitorBubble` + `CacheMonitorPanel`（静态 UI） | 面板能打开/关闭/拖拽 |

| **Step 5** | 差异对比 `CompareView` | 选中两条记录能 diff |
| **Step 6** | 设置集成 + 美化打磨 | 完整可用 |
