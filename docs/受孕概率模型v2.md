# 受孕概率模型 v2

> 从"按时间缩放的速率模型"改为"事件驱动的伯努利试验模型"。
> 解决旧模型中概率被小时稀释为接近零的问题，同时保持及时反馈、不重复判定。

---

## 一、旧模型的问题

### 1.1 旧公式

```
scaledProb = dailyProb × (hoursPassed / 24)
```

### 1.2 问题演示

| 游戏时间推进 | hoursPassed | 日概率 10.2% 的折算结果 | 玩家体感 |
|-------------|-------------|------------------------|---------|
| 5 分钟 | 0.083h | 0.035% (1/2800) | "概率为 0" |
| 30 分钟 | 0.5h | 0.21% (1/470) | "约等于 0" |
| 2 小时 | 2h | 0.85% (1/118) | "聊胜于无" |
| 12 小时 | 12h | 5.1% | "终于像回事了" |

**根因**：医学上的"排卵前日受孕率 25%/天"是一个**事件概率**，不是**每小时的风险率**。你做了全套，概率就是 25%，不因为你用了 5 分钟还是 2 小时而改变。

旧模型把事件概率按时间线性拆分，导致短时间 tick 的概率被稀释到接近无意义。而在实际游戏中，一个游戏日可能只有 3-5 条消息，累积概率远达不到设计意图。

## 二、新模型的数学原理

### 2.1 核心思想

**受孕 = 伯努利试验（Bernoulli Trial），不是泊松过程（Poisson Process）。**

```
每次判定：P(受孕) = 日期系数 × 年龄系数 × 精液系数
         （不乘以任何时间因子）
```

精子的时间维度只影响**能不能活到判定时刻**（通过衰减），不影响**判定概率的大小**。

### 2.2 两个判定触发时机

```
时机 1：新鲜注入（isFreshInjection）
  精液在本 tick 区间内被注入 → 立即判定，使用完整日概率。

时机 2：日期翻篇（dateChanged）
  旧精子存活到了新的一天排卵日 → 判定，使用当天的日期系数。
```

两个时机关联到同一个"是否该判定"条件：

```
shouldRoll = 未孕 AND 精子>0 AND 排卵期 AND (dateChanged OR isFreshInjection)
```

### 2.3 为什么天然不重复、不遗漏

```
时间线演示：

  08:00 tick — lastTickTime=08:00, 精子=0
  12:00 注入精液 (injTime=12:00)
  12:05 tick — lastTickTime=08:00
            → injTime(12:00) > lastTickTime(08:00) → 新鲜！判定！
            → dateChanged? NO
            → 触发一次判定 ✅

  13:00 tick — lastTickTime=12:05
            → injTime(12:00) < lastTickTime(12:05) → 不新鲜
            → dateChanged? NO
            → 跳过 ✅ （不重复）

  14:00 tick — 同上，跳过 ✅

  ─── 午夜，日期翻篇 ───

  次日 tick — dateChanged? YES
            → 精子还活着？衰减后检查
            → 触发判定 ✅ （旧精子跨天获得机会）
```

**不需要任何"今天已经判定过了"的标记**——`lastTickTime` 和 `injTime` 的时间比较天然蕴含了"是否新鲜"的信息。

### 2.4 isFreshInjection 的判断方式

```typescript
// 在 runTickPass 调用层，比对注入时间和上次 tick 时间
let isFresh = false;
const inj = parseWorldTime(uterus.宫内精液.注入时间);
const lastTick = lastTickTime; // 上次 tick 的解析时间
if (inj && lastTick) {
  isFresh = hoursBetween(lastTick, inj) > 0;
}
// 跨多天时 lastTickTime 传 null → isFresh 恒为 false（由 dateChanged 接管）
```

## 三、完整判定公式

### 3.1 公式

```
P = dateCoefficient(cycleDay) × ageCoefficient(age) × semenCoefficient(volume)

判定: Math.random() < P  → 受孕成功
```

没有任何时间缩放因子。

### 3.2 日期系数（不变）

| 周期天数 | 系数 | 医学含义 |
|----------|------|---------|
| 第 14 天 | 0.12 | 排卵前日，受孕率峰值 |
| 第 15 天 | 0.09 | 排卵日 |
| 第 16 天 | 0.05 | 排卵后，卵子失活 |
| 其他 | 0 | 非排卵期，不触发判定 |

三天累积：1 - (1-0.12)(1-0.09)(1-0.05) ≈ 24%，吻合真实每周期 ~25%。

### 3.3 年龄系数（不变）

| 年龄段 | 系数 |
|--------|------|
| < 20 | 1.1 |
| 20-25 | 1.0 |
| 25-30 | 0.9 |
| 30-35 | 0.6 |
| 35-40 | 0.3 |
| ≥ 40 | 0.1 |

### 3.4 精液系数（不变）

6 档锚点 + 线性插值 + 50ml 以上幂函数外推。

## 四、对比总结

| 维度 | 旧模型（按小时缩放） | 新模型（事件驱动） |
|------|---------------------|-------------------|
| 概率公式 | dailyProb × h/24 | dailyProb（不缩放） |
| 5分钟 tick 概率 | ~0.004%（稀释 288 倍） | 完整日概率（立即判定） |
| 判定频率 | 每次 tick 都判定 | 新鲜注入时 + 每天翻篇时 |
| 重复判定 | 会（但概率微小） | 天然不会 |
| 遗漏判定 | 不会（但累积不足） | 不会 |
| 多人公平性 | 只保留最后来源 | 每次新鲜注入独立判定 |
| 数学模型 | 泊松过程（错误） | 伯努利试验（正确） |
| 新增持久变量 | 无 | 无 |
| 新增函数参数 | 无 | isFreshInjection (bool) |

// 旧

## 六、模拟验证

### 场景：张云（43岁），周安注入 5ml，排卵第 14 天

| 时刻 | 触发时机 | 日概率 | 结果 |
|------|---------|--------|------|
| Day14 15:05 (新鲜注入) | isFreshInjection | 0.12×0.1×1.0 = **1.2%** | 判定 |
| Day14 16:00 | 无（已判定过） | — | 跳过 |
| Day15 08:00 (日期翻篇) | dateChanged | 0.09×0.1×0.672 = **0.605%** | 判定 |
| Day16 08:00 (日期翻篇) | dateChanged | 0.05×0.1×0.415 = **0.208%** | 判定 |

累积：1 - (1-0.012)(1-0.00605)(1-0.00208) ≈ 2.0%，吻合 43 岁女性每周期自然受孕率。

### 场景：多人 — 周安(5ml) + X(3ml)，同一天

| 时刻 | 来源 | 触发时机 | 日概率 |
|------|------|---------|--------|
| Day14 10:05 | 周安 | isFreshInjection | 0.12×0.1×1.0 = **1.2%** |
| Day14 15:05 | X（覆盖） | isFreshInjection | 0.12×0.1×0.7 = **0.84%** |
| Day15 08:00 | X（精子存活） | dateChanged | 0.09×0.1×0.485 = **0.437%** |

周安 1 次判定，X 最多 2 次（新鲜 + 跨天）。先注入的被覆盖后失去跨天机会，但获得了当天的一次公平判定。

## 七、扩展：多精液来源支持

> 以下为可选扩展方案。当前先实现单来源版，多来源在需要时再改。

### 7.1 新变量结构

```json
子宫: {
  宫内精液列表: [
    {
      总量: 5,
      来源: "周安",
      注入时间: "2026年04月05日-10:00"
    },
    {
      总量: 3,
      来源: "X",
      注入时间: "2026年04月05日-15:00"
    }
  ],
  生理周期: { ... },   // 不变
  怀孕状态: { ... },    // 不变
  生育记录: [ ... ]    // 不变
}
```

**关键变化**：将原来的单对象 `宫内精液` 改为数组 `宫内精液列表`。

### 7.2 与单槽位的本质区别

| 维度 | 单槽位（覆盖） | 多槽位（数组） |
|------|---------------|---------------|
| A 注入后 B 再注入 | B 覆盖 A，A 消失 | A 和 B 独立存在 |
| A 的跨天机会 | 被覆盖后丧失 | 保留（只要还有余量） |
| 受精后父方确定 | 最后一次来源 | 哪份精液命中就是谁的 |
| AI 写入方式 | 覆盖写入单对象 | push 新条目 |
| 数据结构复杂度 | 低 | 中 |
| 游戏公平性 | 覆盖者"偷走"之前的机会 | 各自独立，各凭本事 |

### 7.3 判定逻辑

```typescript
// 遍历宫内精液列表中的每一条
for (const entry of uterus.宫内精液列表) {
  // 各自独立衰减
  entry.总量 = decay(entry.总量, hoursPassed, phase);
  
  // 各自独立判定（新鲜注入或日期翻篇）
  const isFresh = hoursBetween(lastTickTime, entry.注入时间) > 0;
  if (未孕 && entry.总量 >= 1 && 排卵期 && (dateChanged || isFresh)) {
    const prob = dc × ac × semenCoefficient(entry.总量);
    if (Math.random() < prob) {
      // 命中！记录父方为该条目的来源
      怀孕 = entry.来源;
      break; // 受精后停止
    }
  }
}

// 清理：总量 < 1 的条目移除
uterus.宫内精液列表 = uterus.宫内精液列表.filter(e => e.总量 >= 1);
```

### 7.4 多人模拟

**张云，Day14 排卵窗口，周安(5ml) + X(3ml) + Y(10ml) 三人先后注入：**

```
10:00  周安注入 5ml  → push [{5ml, 周安, 10:00}]
10:05  tick → 周安新鲜: 1.2% → ❌

15:00  X 注入 3ml     → push [{5ml, 周安}, {3ml, X, 15:00}]
15:05  tick → 周安不新鲜(跳过), X新鲜: 0.84% → ❌

20:00  Y 注入 10ml    → push [{5ml, 周安}, {3ml, X}, {10ml, Y, 20:00}]
20:05  tick → 周安跳过, X跳过, Y新鲜: 1.35% → ❌

       —— 三个人，今天全部败北 ——

次日 08:00  tick (dateChanged)
       ├─ 周安: 5 × 0.97^22 = 2.61ml, sc=0.654
       │   日概率 = 0.09 × 0.1 × 0.654 = 0.589% → ❌
       ├─ X:    3 × 0.97^17 = 1.77ml, sc=0.485
       │   日概率 = 0.09 × 0.1 × 0.485 = 0.437% → 🎲 0.003 → ✅！！！
       └─ Y 跳过（X 命中后循环 break）

       → 张云怀孕，父方 = X
       → 周安和 Y 各自获得了公平的判定机会
       → X 骰运最好，在第二天翻篇时命中
```

**单槽位下**：Y 覆盖了 X，只有 Y 有机会跨天。X 完全没机会。

**多槽位下**：三人各有判定机会，X 的低概率逆袭成功。**这才是真正的"各凭本事 + 骰运"。**

### 7.6 扩展的优缺点

**优点**：
- 完整性：每个来源独立存在，不丢失
- 公平性：不因"后来的覆盖先来的"而丧失机会
- 丰富度：多人场景更精彩，产生"是谁的？"的戏剧性
- 判定逻辑自然：遍历列表，命中即停

**缺点**：
- 数据结构复杂度略微上升
- AI 需要知道 push 还是覆盖的语义
- character-filter 的展示需要处理列表（显示"体内残留 3 份精液"）
- 需要确保列表不会无限增长（清理阈值 < 1ml 是安全保障）

### 7.7 向后兼容

老的 `宫内精液`（单对象）可以在 tick 时自动迁移为 `宫内精液列表`（单元素数组），不需要一次性改所有 NPC 数据，也不需要迁移脚本。

```typescript
// 兼容处理
function ensureList(uterus: Uterus): SemenEntry[] {
  if (uterus.宫内精液列表) return uterus.宫内精液列表;
  if (uterus.宫内精液 && uterus.宫内精液.总量 > 0) {
    return [{
      总量: uterus.宫内精液.总量,
      来源: uterus.宫内精液.来源,
      注入时间: uterus.宫内精液.注入时间,
    }];
  }
  return [];
}
```
