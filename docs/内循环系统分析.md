# 内循环系统（明月秋青脚本）分析报告

> 文件来源：`game/src/内循环系统.json`（259KB，SillyTavern 脚本扩展格式）
> 名称："明月秋青脚本"，内部代号"**智脑**"
> 运行环境：SillyTavern 前端，通过 `injectPrompts` 向 AI 提示词注入数据

---

## 一、系统架构总览

这是一个为 AI 叙事游戏设计的多层 NPC 仿真与玩家行为分析系统。它不直接控制游戏逻辑，而是**在提示词层面**注入结构化数据，让 AI 在生成叙事时自然参考这些数据。

核心循环：**正文捕获 → 大总结 → 梦呓分析 → 倒果为因 → 情绪积累 → 注入提示词**

```
每 N 轮触发一次
    ↓
[正文捕获] → 收集最近 N 轮的 maintext
    ↓
[大总结] → 结构化整理：时间线 + 角色记忆 + 动态人设
    ↓
[梦呓分析] → 分析玩家行为：游玩类型 + 行为模式 + 喜好
    ↓
[倒果为因] → 预测剧情方向：5 个可能的未来转折点
    ↓
[情绪积累] → 更新每个角色对玩家的多维情绪值
    ↓
[注入提示词] → 将以上全部数据注入 AI 上下文
```

---

## 二、六大模块详解

### 2.1 大总结（Grand Summary）

**触发条件**：每 N 轮对话自动触发（"X 楼触发"，可配置间隔）

**处理流程**：
1. 收集本次需要总结的正文日志
2. 如果有前次大总结，先加载旧数据
3. AI 按严格格式整理为四个部分

**输出结构**：

| 部分 | 内容 | 规则 |
|------|------|------|
| 时间线摘要 | 按日期编号的事件叙事 | 旧事件保留原编号，新事件接续编号；禁止修辞；日期从正文时空栏提取 |
| 角色记忆 | 每个出场角色的第一人称记忆 | 永久记忆保留前次，新增记忆标记为 NEW；区分永久/新增两类 |
| 动态人设 | 角色当前状态变化 | 不是重写人设，而是写剧情发展后的变化：情绪状态、关系变化、行为模式变化 |
| 亲密记录 | 性爱/亲密场景（可选） | 仅在日志包含时输出，与日常记忆完全隔离 |

**记忆的情感偏差规则**（核心创意）：
- **好感 > 0 的角色**：记住更多细节，细节清晰到天气和穿着
- **好感 < 0 的角色**：记忆存在恶意抹黑和偏差，选择性记住不舒服的地方
- **好感 = 0 的角色**：对非重要的事记不住，或只有模糊概念

**安全检查**：如果角色记忆数量锐减超过 50%，放弃本次总结（防止 AI 幻觉破坏数据）

---

### 2.2 梦呓分析（Dream Murmur）

**目的**：深度理解玩家行为，让 AI 叙事更贴合玩家风格

**分析维度**：

| 维度 | 说明 |
|------|------|
| 游玩类型 | 代入式（完全代入角色，只写对话和简单动作）/ 大纲流（像作者一样写大段剧情）/ 混合型 |
| 通用行为模式 | 各种情绪下的习惯动作、说话习惯、场景中的存在方式 |
| 专属交互模式 | 与每个 NPC 的交互模式：靠近时/被触碰时/冲突时/亲密时的典型行为 |
| 喜欢的方向 | 被保留的正文有什么共性 |
| 不喜欢的方向 | 被 reroll 掉的正文有什么共性 |
| 性癖偏好 | 节奏偏好/场景方向（仅在含性爱内容时输出） |

**关键原则**：
- 行为模式必须是**具体动作**，不是标签
- 证据不足时输出"证据不足，待观察"
- 偏好与日常行为模式完全独立，不混淆

---

### 2.3 倒果为因（Reverse Causality）

**目的**：让 AI 对剧情方向有"远见"，但不强制推进

**输出**：恰好 5 个可能的未来转折/结局方向（称为"果"），每个包含：
- 类别：角色关系张力 / 未解决的伏笔 / 角色内在矛盾 / 外部事件趋势 / 用户行为模式
- 概率：0-100%（独立评估，总和不为 100）
- 具体可执行的描述

**维护规则**（每次大总结后）：
1. 删除已被剧情否定的果（概率设为 0%）
2. 调整存活果的概率
3. 根据新剧情补充新的果到 5 个

**节奏判定**：开局 → 发展 → 高潮 → 收束

**约束**：方向仅供 AI 创作时参考，"不主动推进，用户的选择优先"

---

### 2.4 情绪积累（Emotion Accumulation）

**数据结构**：每个角色对玩家维护 N 个情绪维度，每个维度 { 值: -100~100, 趋势: ↑↓→, 上次变动楼层, 原因 }

**衰减规则**（按角色性格差异化）：

| 角色类型 | 衰减特征 |
|----------|----------|
| 记仇型 | 恨意衰减极慢（几十楼才 -1） |
| 大咧咧型 | 大部分情绪衰减快 |
| 深情型 | 依赖几乎不衰减 |
| 多疑型 | 信任衰减快，恨意衰减慢 |

**积累规则**：
- 单次事件通常 +10~20（极端事件可到 ±40）
- 重复同类事件边际效应递减（第一次送礼 +15，第三次送礼 +5）
- 负面事件 > 正面事件（人类心理偏差）
- 角色最近没出场 → 保持上次状态或自然衰减

**输出格式**：`情绪名: 值 趋势 — 原因（≤10字）`

---

### 2.5 性格调色盘（Personality Palette）

一套完整的角色性格分析框架，用于指导 AI 理解角色。

**颜色隐喻**：

| 层级 | 含义 | 特征 |
|------|------|------|
| 底色 | 角色最稳定、最不易消失的核心质地 | 无论什么状态都隐隐存在 |
| 主色调 | 日常最常驱动行为的颜色 | 最常被看见 |
| 点缀色 | 负责反差和余味的隐藏层 | 特定压力下才出现 |

**衍生规则**：每种颜色必须衍生为"具体场景下的具体行为描述"，不能停在标签。例如"温柔的衍生 = 用照顾来确保对方不离开"。

**性格对冲**：角色内部必须有互相拉扯的颜色。例如"叛逆与依赖对冲：越想证明不需要任何人，越会在撑不住时暴露本能依赖"。

**混色写法**：同一个动作里两种以上情绪同时存在。用物理事实做反差，不解释，让读者自己完成混色。混色是点睛之笔，不是每个瞬间都需要。

**核心人格层**：表层欲望 → 深层缺失 → 核心恐惧 → 防御机制（必须是行为）→ 核心矛盾（一句话说清）→ 道德底线（什么绝对不会做 + 什么极限下可能被逼到边缘）

**三面性**（如适用）：同一台发动机在不同压力场景下切换档位，每张面包含触发条件、能量状态、行为模式

---

### 2.6 记忆激活与提示词注入

在大总结后，将结构化数据注入 AI 提示词：

```
[动态人设] → 角色当前状态（与原始人设冲突时优先）
[神经链记忆] → 基于关键词激活的角色记忆（核心记忆 + 近期记忆）
[梦呓数据] → 玩家游玩类型 + 行为模式 + 交互模式 + 喜好/厌恶
[倒果为因] → 5 个剧情可能方向（仅供参考）
[情绪状态] → 各角色对玩家的情绪值（通过微表情/语气/小动作自然流露）
[人格画像] → 深度分析后的角色人格描述
[隔离声明] → 性爱场景与日常场景完全切割
```

## 三、UI 设计

- **悬浮按钮**（FAB）：可拖动的圆形浮动按钮，移动端友好
- **面板**：可调整大小的弹出面板，支持拖动、调整大小、手机下拉关闭手势
- **标签页**：角色库 / 大总结 / 梦呓数据 / 偏好编辑 / 状态仪表盘
- **角色管理**：多人设管理、导入导出、当前激活人设编辑

---

## 四、设计哲学

1. **角色是矛盾体**：不是标签集合。性格对冲、混色瞬间、三面性是核心驱动力
2. **记忆有偏差**：角色的情感态度决定记忆的保真度，不是客观记录
3. **数据整理而非创作**：每个分析模块强调"这是数据整理"，用严格格式约束 AI
4. **隔离原则**：性爱场景与日常场景完全切割，"做爱前是什么性格，做爱后还是什么性格"
5. **不越界**：剧情预测只提供参考，"用户的选择优先，不要生硬推进"
6. **增量式演进**：保留旧记忆、接续旧编号、调整已有概率——不是每次重来
7. **系统是隐形的**：玩家不直接看到情绪值/概率，AI 通过叙事自然体现

## 五、与当前项目的关系

该 JSON 文件位于 `game/src/` 下，但**当前项目代码并未加载它**。它是一个独立的 SillyTavern 脚本扩展。

其核心模块可以作为当前项目升级的参考蓝图：

| 内循环系统模块 | 可应用于当前项目 |
|---------------|-----------------|
| 大总结 | 升级 plotHistory 的生成质量和结构化程度 |
| 梦呓分析 | 新增玩家行为分析，让 AI 自适应玩家风格 |
| 倒果为因 | 让 AI 在叙事时有更连贯的"远见" |

| 记忆激活 | 增强当前 lorebook 的触发机制，改为角色记忆链注入 |
