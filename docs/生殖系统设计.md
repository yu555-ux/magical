# 生殖系统设计

> 纯规则驱动的生理模拟。代码负责全部计算，AI 只读取结果用于叙事。
>
> 实现文件：`game/src/sillytavern/physiology.ts`

---

## 一、变量结构

每个女性人物节点下包含 `子宫` 字段：

```yaml
子宫:
  宫内精液:
    总量: 8                             # number, 所有来源.容量之和（代码自动同步）
    来源列表:                            # Array, 按注入时间排序
      - 来源: "周安"                     # string, 注入者
        容量: 5                         # number, ml（该来源独立衰减后的剩余量）
        注入时间: "2026年04月06日-10:00"  # string, 格式 "YYYY年MM月DD日-HH:MM"
      - 来源: "X"
        容量: 3
        注入时间: "2026年04月06日-15:00"

  生理周期:
    上次经期日: "2026年03月28日"
    周期天数: 28
    经期长度: 5
    当前阶段: "排卵期"            # 代码写入，AI 只读

  怀孕状态:
    状态: "未孕"
    受孕日期: null
    父方: null

  生育记录: []                   # AI 写入，每次分娩追加
```

**初始值（未孕女性默认）**：

```yaml
宫内精液:  { 总量: 0, 来源列表: [] }
生理周期:  { 上次经期日: "2026年03月28日", 周期天数: 28, 经期长度: 5, 当前阶段: "安全期" }
怀孕状态:  { 状态: "未孕", 受孕日期: null, 父方: null }
生育记录:  []
```

不同 NPC 的 `上次经期日` 和 `周期天数` 需要手动错开。

## 二、时间工具

### 2.1 世界时间格式

```
世界.现实.时间 = "2026年04月06日-星期一-20:00"
```

### 2.2 解析

```
正则: /(\d{4})年(\d{2})月(\d{2})日.*?(\d{2}):(\d{2})/

→ { year: 2026, month: 4, day: 6, hour: 20, minute: 0 }
```

### 2.3 日期/时间差

```
daysBetween(a, b)  = 两个日期字符串之间的天数（Date 差值 / 86400000）
hoursBetween(a, b) = 两个 ParsedTime 之间的小时数
advanceDate(d, n)  = 日期字符串 + n 天
```

### 2.4 tick 调度

- 世界时间每次变化时触发一次 tick
- 跨多天时逐日迭代（每天 24h, dateChanged=true），确保衰减、周期、判定中间状态不丢
- 小时差 = 0 时跳过

## 三、生理周期

### 3.1 当前天数

```
daysSincePeriod = daysBetween(上次经期日, 世界日期)
currentDay      = (daysSincePeriod % 周期天数) + 1
```

`currentDay` 范围 `1 ~ 周期天数`。

### 3.2 阶段判定

| 天数范围 | 阶段 |
|----------|------|
| 1 ~ 经期长度 | **经期** |
| (经期长度+1) ~ 13 | **安全期** |
| 14 ~ 16 | **排卵期** |
| 17 ~ 周期天数 | **安全期** |

14 和 16 是排卵期的固定锚点（对应 28 天标准周期）。非常规周期（如 26 天）排卵窗口相对位置不变。

### 3.3 怀孕期间冻结

当 `状态 ≠ "未孕"` 时跳过周期计算。黄体酮抑制排卵和月经，`上次经期日` 冻结不动。产后恢复时重置。

### 3.4 经期首日自动推进

当 `daysSincePeriod >= 周期天数` 时，`上次经期日` 推进一个周期，确保 `currentDay` 始终在有效范围内。

## 四、宫内精液衰减

### 4.1 衰减率

| 阶段 | 衰减率/小时 | 24h 后剩余 | 依据 |
|------|-----------|----------|------|
| **排卵期** | **0.97** | 48% | 宫颈黏液稀薄碱性，精子存活 3-5 天 |
| **非排卵期** | **0.85** | 2% | 宫颈黏液黏稠酸性，精子快速死亡 |

### 4.2 公式

```
总量 = round(总量 × 衰减率^hoursPassed)
```

对非排卵期（衰减快）和排卵期（衰减慢）自动切换。同日 tick 相位不变，跨夜 tick 微量近似可忽略。

### 4.3 归零

```
if 总量 < 1:
    总量 = 0, 来源 = null, 注入时间 = null
```

## 五、怀孕状态机

### 5.1 状态流转

```
未孕 ──[受精判定通过]──▶ 受精 ──[孕2周]──▶ 早孕 ──[孕14周]──▶ 中孕 ──[孕28周]──▶ 晚孕 ──[孕38周]──▶ 产褥期 ──[产后6周]──▶ 未孕
```

妊娠全程 266 天（38 周），从受孕日起算。

### 5.2 概率模型

**核心公式**：

```
P = dateCoefficient × ageCoefficient × semenCoefficient
```

- **不按小时缩放**。受孕是伯努利试验（事件概率），不是泊松过程（风险率）。
- 精子的时间维度只影响衰减（能否活到判定时刻），不影响单次判定概率的大小。

#### 日期系数

| 周期天数 | 系数 | 医学含义 |
|----------|------|---------|
| 第 14 天 | **0.12** | 排卵前日，受孕率峰值 |
| 第 15 天 | **0.09** | 排卵日 |
| 第 16 天 | **0.05** | 排卵后，卵子失活 |
| 其他 | 0 | 非排卵期，不触发 |

三天累积：1 - (1-0.12)(1-0.09)(1-0.05) ≈ **24%**，吻合真实每周期 ~25%。

#### 年龄系数

| 年龄段 | 系数 |
|--------|------|
| < 20 | 1.1 |
| 20-25 | 1.0 |
| 25-30 | 0.9 |
| 30-35 | 0.6 |
| 35-40 | 0.3 |
| ≥ 40 | 0.1 |

#### 精液系数

6 档锚点 + 线性插值 + 50ml 以上幂函数外推：

| 精液量 | 系数 |
|--------|------|
| 1ml | 0.35 |
| 3ml | 0.7 |
| 5ml | 1.0 |
| 10ml | 1.35 |
| 20ml | 1.6 |
| 50ml | 3.0 |
| > 50ml | 3.0 × (量/50)^1.2 |

### 5.3 判定触发时机（事件驱动）

**不是每次 tick 都判定。** 仅在以下两种时机触发：

| 时机 | 条件 | 触发标签 | 概率 |
|------|------|---------|------|
| 🆕 **新鲜注入** | `注入时间` 发生变化（prev ≠ curr） | `'fresh'` | 完整日概率 |
| 📅 **日期翻篇** | 游戏日期改变 | `'daily'` | 完整日概率 |

三个前置条件（缺一不可）：
1. `怀孕状态.状态 = '未孕'`
2. `宫内精液.总量 > 0`
3. `生理周期.当前阶段 = '排卵期'`

#### 新鲜注入的检测方式

```
runTickPass 从 preVars（AI 合并前快照）读取旧注入时间，与当前注入时间比对：
  注入时间 !== null && 注入时间 !== prevInjTime → 新鲜注入
```

**为什么从 preVars 读而非当前状态**：`useSillytavern.ts` 的 semenPatches 循环会在 tick 前把注入时间重写为当前世界时间。如果从当前状态读，读到的就是刚被改过的值，永远判不出"变化"。

#### 判定频率

- 同一份精液：注入时判定 1 次，之后每天日期翻篇时判定 1 次（直到衰减归零或离开排卵窗口）
- 不同人先后注入同一人（覆盖）：各自获得独立的"新鲜注入"判定，但后来者的精液覆盖先来者
- 同一天内多次 tick：不会重复判定（注入时间没变，日期也没变）

```
示例：张云 43 岁，Day14 排卵前日，周安注入 5ml

  Day14 15:05 (新鲜注入): P = 0.12×0.1×1.0 = 1.20%  → 🎲
  Day14 16:00:            注入时间未变、日期未变 → 跳过
  Day15 08:00 (日期翻篇):  P = 0.09×0.1×0.654 = 0.59% → 🎲
  Day16 08:00 (日期翻篇):  P = 0.05×0.1×0.415 = 0.21% → 🎲
  Day17 08:00 (日期翻篇):  安全期 → 跳过

  累积: 1 - 0.988×0.9941×0.9979 ≈ 2.0%，吻合 43 岁现实数据
```

### 5.4 随机判定

```
rolled = Math.random()           // [0, 1) 均匀分布
if rolled < P → 受精成功
```

成功时：

```
怀孕状态.状态    = "受精"
怀孕状态.受孕日期 = 当前世界日期
怀孕状态.父方    = 宫内精液.来源
```

### 5.5 孕周计算

```
孕周 = floor(daysBetween(受孕日期, 当前世界日期) / 7)
```

以受孕日期为孕 0 周起点。

### 5.6 怀孕阶段推进（仅 dateChanged 时）

| 孕周范围 | 状态 |
|----------|------|
| 0 ~ 1 | **受精** |
| 2 ~ 13 | **早孕** |
| 14 ~ 27 | **中孕** |
| 28 ~ 37 | **晚孕** |
| ≥ 38 | → **产褥期** |

### 5.7 分娩

孕周 ≥ 38 且状态仍为 `晚孕` → 状态切为 `产褥期`。AI 应在叙事中向 `生育记录` 追加记录。

### 5.8 产褥期

```
产后天数 = daysBetween(受孕日期 + 266天, 当前世界日期)
当 产后天数 >= 42（6周）:
    状态 = "未孕", 受孕日期 = null, 父方 = null
    上次经期日 = 当前世界日期, 当前阶段 = "经期"
```

## 六、tick 执行流程

```
tickAllFemales(variables, oldTime, newTime, {prevVariables: preVars})
│
├─ 首次 tick (oldTime=null)
│   └─ runTickPass(dateChanged=false, hoursPassed=0) → 仅初始化周期
│
├─ 跨多天 (daysPassed > 1)
│   └─ for each day:
│       runTickPass(dateChanged=true, hoursPassed=24, prevVariables=null)
│       → 每天判定一次，由 dateChanged 接管
│
└─ 同日或跨 1 天
    └─ runTickPass(dateChanged, hoursPassed, prevVariables=preVars)
        │
        └─ 遍历每个女性角色:
            │
            ├─ 从 prevVariables 读取 prevEntries（旧来源列表）
            │
            └─ tickFemalePhysiology(uterus, dateStr, age, hoursPassed,
                                     dateChanged, prevEntries)
                │
                ├─ 1. 更新生理周期（dateChanged && 未孕）
                ├─ 2. 多来源独立衰减（遍历来源列表，<1ml 移除，同步总量）
                ├─ 3. 遍历来源列表判定（指纹比对 isFresh || dateChanged）
                │     命中 → 父方=该条目来源，清空列表，break
                ├─ 4. 怀孕阶段推进（dateChanged）
                └─ 5. 产褥期恢复（dateChanged）
```

### 关键函数

| 函数 | 位置 | 职责 |
|------|------|------|
| `tickAllFemales` | `physiology.ts` | 入口：解析时间、分派逐日/同日、协调现实和梦境 |
| `runTickPass` | `physiology.ts` | 遍历女性角色、从 prevVariables 提取旧来源列表 |
| `tickFemalePhysiology` | `physiology.ts` | 多来源衰减 + 遍历判定 + 怀孕状态推进 |
| `buildFingerprint` | `physiology.ts` | 构建旧来源列表的 `来源:注入时间` 指纹集合 |
| `semenPatches` 循环 | `useSillytavern.ts` | AI 修改精液后补全注入时间、自动迁移旧结构、同步总量 |
| toast 展示 | `ChatPage/index.tsx` | `FertilizationResult` → 右上角 toast |

## 七、与第二 API 的衔接

### 7.1 精液注入流程

```
1. AI 响应中包含 <JSONPatch>，修改 宫内精液.总量
2. 第二 API 解析 patch → varsUpdated = true
3. semenPatches 循环检测到 总量 变化 → 重写 注入时间 为当前世界时间
4. tickAllFemales 运行 → runTickPass 从 preVars 读取旧注入时间
5. 检测到 注入时间 变化 → isFreshInjection = true → 触发受精判定
6. FertilizationResult 返回 → ChatPage 展示 toast
```

### 7.2 关键设计

- **注入时间由代码管理**：AI 只需写 `总量` 和 `来源`，`注入时间` 由 semenPatches 循环强制重写。避免 AI 写错时间导致判定失败。
- **prevVariables 快照**：`preVars` 记录 AI 合并前的变量状态，用于对比注入时间是否发生变化。
- **单 API 模式注意**：目前 semenPatches 仅在双 API 模式下生效。单 API 模式下 AI 直接通过 `<vars>` 写 `注入时间`，需确保 AI 正确写入。

```json
[{"op": "replace", "path": "/主要人物/女性/异人/张云/子宫/宫内精液/总量", "value": 5},
```

```typescript
export interface FertilizationResult {

  semenCoeff: number;      // 精液系数
```

## 附录：多精液来源（已实施）

### A.1 数据结构

```yaml
宫内精液:
  总量: 8                          # sum(来源列表[*].容量), 代码自动同步
  来源列表:
    - 来源: "周安"
      容量: 5                      # 该来源独立衰减后的剩余量
      注入时间: "2026年04月05日-10:00"
    - 来源: "X"
      容量: 3
      注入时间: "2026年04月05日-15:00"
```

### A.2 核心规则

| 规则 | 说明 |
|------|------|
| 独立衰减 | 每个条目独立衰减，互不影响 |
| 独立判定 | 按注入时间排序遍历，每条独立判定 |
| 命中即停 | 命中 → 父方=该条目来源，清空列表 |
| 总量同步 | 衰减/清理后 `总量 = sum(来源列表[*].容量)` |
| 清理阈值 | `容量 < 1ml` → 从列表移除 |

### A.3 新鲜注入检测

旧来源列表构建指纹集合（`来源:注入时间`）。当前列表中不在指纹集合中的条目视为新鲜注入。

### A.4 AI 写入

AI 通过 JSONPatch 写入 `来源列表`。代码自动补全缺失的 `注入时间` 并同步 `总量`。

### A.5 向后兼容

首次 tick 检测到旧 `{ 总量, 来源, 注入时间 }` 结构时自动迁移为 `{ 总量, 来源列表: [...] }`。
