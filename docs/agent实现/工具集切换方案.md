# 工具管理方案（最终版）

> 2026-06-17
> **结论：不做场景过滤，不做工具集切换。22 个工具全部始终可见。**
> 
> 参考：fate-sandbox（32 个工具全暴露，无任何过滤机制）。

---

## 决策过程

1. **最初设计**：`switch_scene` + `SCENE_VARIABLE_TOOLS` 白名单，按场景过滤 variable 类工具
2. **讨论工具集切换**：参考 tavern2agent 的 `switch_toolset` 建议，考虑做命名工具组切换
3. **审计发现问题**：
   - `upsert_actor` 不在任何白名单中（场景激活后消失，是个 bug）
   - `update_npc_info` 只在 exploration + social 可见（战斗/亲密/梦境中缺失）
   - 场景过滤只覆盖 variable 类别，不完整
   - 循环中间切换场景后工具列表不更新（`openaiTools` 在循环外冻住）
4. **最终决策**：去掉场景过滤。22 个工具全部始终可见，和 fate-sandbox 一致。

## 理由

- 22 个工具的 token 开销可接受（签名总计约 3000-4000 token）
- 白名单维护负担 > 收益
- AI 选工具的真正防线是 description + tool-policy 路由规则，不是过滤
- fate-sandbox 证明了这个做法的可行性（32 个工具全暴露）

## 下一步：真正的防线

既然不做工具过滤，就需要加强 AI 选对工具的引导。按优先级：

1. **补全所有工具的 description 三段式**（必须调用/严禁/你的职责）
2. **更新 tool-policy 路由规则**（补充 NPC 互动后的更新规则、跨工具聚合规则）
3. **给所有写工具加 reason 引导**（"reason 应描述因果，不是标签"）
4. **story-driver 自我提问**（引导 AI 每轮自问"哪些状态需要工具裁决"）
