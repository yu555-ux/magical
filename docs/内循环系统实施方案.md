## 一、第一阶段：自动摘要注入（大总结简化版）

> 目标：让 AI 每 N 轮自动获得一份「前情提要」，不再依赖 AI 自己输出 `<history>` 标签。
> 工作量：~150 行新代码，1 个新文件。

### 1.1 数据结构

```typescript
// types.ts 新增

interface WorldSummary {
  /** 最后一次摘要覆盖到的 messageId */
  lastSummaryAtMessageId: string;
  /** 摘要轮次 */
  summaryRound: number;
  /** 时间线 */
  timeline: SummaryTimelineEntry[];
  /** 角色记忆（按角色名索引） */
  characterMemories: Record<string, SummaryMemory[]>;
  /** 动态人设（按角色名索引） */
  dynamicPersonas: Record<string, string>;
  /** 生成时间戳 */
  generatedAt: number;
}

interface SummaryTimelineEntry {
  id: number;            // 全局自增编号
  date: string;
  world: '现实' | '梦境';
  location: string;
  event: string;         // 一句话事件描述
}

interface SummaryMemory {
  eventId: number;
  date: string;
  content: string;       // 第一人称，带情感偏差
  isNew: boolean;
}
```

### 1.2 触发逻辑

```
sendGameMessage 末尾：

1. 检查 pendingCount（未摘要的 assistant 消息数）
2. pendingCount >= SUMMARIZE_INTERVAL（默认 5）→ 触发
3. 收集待摘要的 maintext 数组
4. 调第二 API 生成摘要
5. 存储到 ChatSession.worldSummary
6. 下一轮 assemblePrompt 自动注入
```

```typescript
// useSillytavern.ts 中 sendGameMessage 末尾新增

const SUMMARIZE_INTERVAL = 5;

// 计算待摘要数量
const lastSummaryId = updatedChat.worldSummary?.lastSummaryAtMessageId ?? '';
const pendingMessages = updatedChat.messages
  .filter(m => m.role === 'assistant' && m.id > lastSummaryId && m.parsed?.maintext);

if (pendingMessages.length >= SUMMARIZE_INTERVAL) {
  // 异步触发摘要（不阻塞主流程）
  triggerWorldSummary(updatedChat, pendingMessages, effectiveSettings).then(result => {
    if (result) {
      // 静默更新 worldSummary，下一轮自动生效
      updateChatWorldSummary(updatedChat.id, result);
    }
  });
}
```

### 1.3 摘要生成

```typescript
// 新文件：sillytavern/world-summary.ts

export async function generateWorldSummary(
  previousSummary: WorldSummary | null,
  newMaintexts: Array<{ messageId: string; content: string }>,
  settings: AppSettings,
): Promise<WorldSummary | null> {
  const router = createApiRouter(settings.api);
  const prompt = buildSummaryPrompt(previousSummary, newMaintexts, settings);

  try {
    const { response } = await router.call('vars', {
      messages: [{ role: 'user', content: prompt }],
      stream: false,
      temperature: 0.3,
      max_tokens: 4096,
    }, new AbortController().signal);

    if (!response.ok) return null;
    const json = await response.json();
    const raw = json?.choices?.[0]?.message?.content ?? '';

    // 解析 AI 返回的 JSON 结构
    return parseSummaryResponse(raw, previousSummary, newMaintexts);
  } catch {
    return null;
  }
}
```

### 1.5 关键设计决策

- **异步触发**：摘要生成不阻塞本轮回复（用 `triggerWorldSummary().then()`）
- **下一轮生效**：本轮玩家看到的是当前的 AI 回复，下一轮才注入新摘要
- **增量合并**：前次摘要的时间线/记忆保留，新事件接续编号
- **容错**：解析失败 → 静默跳过，不影响游戏

## 二、第二阶段：情绪积累（轻量版）

> 目标：角色对玩家的态度不再是静态好感值，AI 能感知「她最近更信任你了」。
> 工作量：~120 行新代码，0 新文件（扩展现有结构）。

### 2.1 定位

**不做**完整的 -100~100 多维情绪系统（太重）。
**做**基于现有「好感值」变量的**变化趋势追踪**。

```
每一次 sendGameMessage 后：
  preVars.好感值 → postVars.好感值 → delta = post - pre

积累：
  affectionTrend[characterName] = {
    shortTerm: 最近3轮的变化总和,
    longTerm:  最近10轮的变化总和,
    peakValue: 历史最高值,
    lastDirection: '↑' | '↓' | '→',
  }
```

### 2.2 数据结构

```typescript
// types.ts 新增

interface AffectionTrend {
  /** 短期变化（最近 3 轮） */
  shortTermDelta: number;
  /** 长期变化（最近 10 轮） */
  longTermDelta: number;
  /** 历史峰值 */
  peakValue: number;
  /** 最近一次变化方向 */
  lastDirection: 'up' | 'down' | 'flat';
  /** 最后变动轮次 */
  lastChangeRound: number;
}

// ChatSession 新增字段
interface ChatSession {
  // ... 现有字段 ...
  affectionTrends?: Record<string, AffectionTrend>;
}
```

### 2.3 触发逻辑

```typescript
// useSillytavern.ts 的 sendGameMessage 中，
// 在 buildVarChanges 之后新增

// 从 varChanges 中提取所有「好感值」变化
const affectionDeltas: Record<string, number> = {};
for (const c of varChanges ?? []) {
  if (c.path.endsWith('好感值') && c.category === 'numeric') {
    const name = extractCharacterName(c.path);  // '主要人物.顾昀.好感值' → '顾昀'
    affectionDeltas[name] = c.delta ?? 0;
  }
}

// 更新趋势
const trends = { ...(chat.affectionTrends ?? {}) };
for (const [name, delta] of Object.entries(affectionDeltas)) {
  const prev = trends[name] ?? { shortTermDelta: 0, longTermDelta: 0, peakValue: 0, lastDirection: 'flat' as const, lastChangeRound: 0 };
  const shortTermDelta = prev.shortTermDelta + delta;
  const longTermDelta = prev.longTermDelta + delta;
  const currentValue = prev.peakValue + delta; // 从 delta 推算当前值
  trends[name] = {
    shortTermDelta,
    longTermDelta,
    peakValue: Math.max(prev.peakValue, currentValue),
    lastDirection: delta > 0 ? 'up' : delta < 0 ? 'down' : prev.lastDirection,
    lastChangeRound: chat.messages.length,
  };
}
```

### 2.4 提示词注入

注入到 `<emotion_state>` 段：

```xml
<emotion_state>
角色对{{user}}的态度变化（通过微表情/语气/小动作自然流露，勿直白描述）：
- 顾昀：短期↑（信赖加深），长期↑（持续升温）
- 张云：短期→（稳定信任），长期↑
</emotion_state>
```

### 2.5 关键设计决策

- **不新建情绪维度**：直接从现有好感值派生，零配置成本
- **只追踪趋势**：不要求 AI 输出情绪，只计算已有的数值变化
- **注入提示词而非存储值**：AI 看到「信赖加深」而不是「好感=44」
- **自然衰减不做**：太复杂，留到后续迭代

## 三、第三阶段：梦呓分析 + 倒果为因（可选）

> 这两项的核心价值是让 AI「理解玩家」和「有远见」，但都需要额外的 AI 调用和较复杂的解析逻辑。
> 建议在第一、二阶段稳定运行后再启动。

### 3.1 梦呓分析（轻量版）

不在每 N 轮触发，而是在**玩家手动触发**时运行（降低 token 消耗）：


## 五、不做的事情（明确边界）

- ❌ 完整 -100~100 多维情绪系统 → Phase 2 只用好感趋势
- ❌ 性格调色盘（Personality Palette）→ 太复杂，暂不实施
- ❌ 记忆偏差引擎（好感影响记忆）→ Phase 1 摘要含情感偏差提示即可
- ❌ FAB 悬浮按钮 + Panel UI → 当前项目已有自己的设置面板体系
- ❌ localStorage 持久化 → 用 IndexedDB（项目已有）
- ❌ `injectPrompts` 机制 → 用 `assemblePrompt` stage 系统（项目已有）
- ❌ 性爱场景隔离 → 当前项目通过 `<maintext>` 标签天然隔离

## 七、回滚与兼容性

- `worldSummary` 字段可选（`?`），旧存档无此字段不受影响
- 摘要生成失败 → 静默跳过，下次继续尝试
- 可通过设置 `SUMMARIZE_INTERVAL = 0` 关闭功能
- 不改变现有 `<history>` 标签行为（两者共存，摘要作为补充）
