# Agent 异步循环设计

## 概述

当前游戏只有一条主线：玩家发消息 → AI 回复 → 变量更新 → 生理 tick。世界在其他时间静止。
Agent 异步循环是第二条线，让 NPC 和世界在后台自主运行。

---

## 三层 Agent 模型

### 第一层：确定性 Agent（纯规则，无 API）

| Agent | 触发条件 | 描述 |
|-------|----------|------|
| 生理 tick | 时间变化 | 已有的生殖系统模拟（精液衰减、月经周期、怀孕推进） |
| NPC 位置巡游 | 时间变化 | NPC 按预设路线/状态机在各地间移动 |
| 关系值衰减 | 时间变化 / 每 N 轮对话 | 好感度、信任度等数值随时间自然衰减或向基线回归 |
| 物品状态更新 | 时间变化 | 食物腐坏、物品耐久下降等 |

### 第二层：本地推理 Agent（轻量 API，单次调用）

| Agent | 触发条件 | 描述 |
|-------|----------|------|
| NPC 短时意图 | 时间变化 + 地点切换 | 给时间 + NPC 性格 + 当前状态 → 输出"想去哪儿/做什么/和谁互动" |
| 关系微调 | 每 N 轮对话 | 给双方 history + 近期互动事件 → 决定好感度变化方向和幅度 |
| 传言扩散 | 时间变化 / 地点切换 | 给地图 + 近期公共事件 → 决定哪些 NPC 听说了什么 |

### 第三层：叙事 Agent（完整 API，低频调用）

| Agent | 触发条件 | 描述 |
|-------|----------|------|
| 场景快照 | 时间推进超过 N 小时 | 生成 NPC 群体的活动摘要，供 AI 叙事引用 |
| 人物成长 | 累积足够互动量 | 更新 NPC 性格、记忆、人际关系网 |
| 世界事件 | 时间推进 / 手动触发 | 对宏观局势做一次推进（政治、经济、灾难等） |

---

## 触发机制

| 触发方式 | 事件名 | 适合 | 不适合 |
|----------|--------|------|--------|
| 时间变化 | `time_changed` | 确定性 tick、NPC 巡游、场景快照 | — |
| 地点切换 | `location_changed` | 新地点 NPC 状态刷新、传言扩散 | — |
| N 轮对话 | `chat_turns` | 关系更新、宏观推进 | 高频任务 |
| 闲置 | `idle` | 叙事 agent、世界推进 | 确定性任务 |
| 手动触发 | `manual` | 强制推进、调试 | — |

核心原则：**避免与玩家对话争抢 API**。玩家输入优先，Agent 在间隙运行。

## Agent 调度器

```typescript
interface GameAgent {
  id: string;
  /** 触发条件 */
  trigger: 'time_changed' | 'location_changed' | 'chat_turns' | 'idle' | 'manual';
  /** 最小间隔（避免频繁调用） */
  cooldownMs: number;
  /** 是否需要 LLM */
  needsLLM: boolean;
  /** 优先级（同触发条件下数值小的先执行） */
  priority: number;
  /** 是否阻塞主对话（叙事 agent 通常不阻塞） */
  blocking: boolean;
  /** 执行 */
  run(vars: GameVariables, context: AgentContext): Promise<AgentResult | null>;
}

interface AgentResult {
  /** 变量补丁，合并进游戏状态 */
  patch: VariablePatch;
  /** 可选：系统消息，插入聊天记录展示给玩家 */
  systemMessage?: string;
  /** 可选：通知展示在 UI */
  notification?: { title: string; message: string };
}
```

### 调度流程

```
触发条件满足
  → 收集该触发条件下的所有 agent
  → 按 priority 排序
  → 串行执行（确定性先，LLM 后）
  → blocking agent 执行时玩家等待
  → non-blocking agent 结果异步回填
  → 合并所有 patch 到变量
  → 可选系统消息/通知展示
```

## 事件总线

```
time_changed event（世界时间推进）
  ├── [P1 确定性] 生理 tick
  ├── [P2 确定性] NPC 位置巡游
  ├── [P3 确定性] 关系值衰减
  ├── [P4 确定性] 物品状态更新
  ├── [P5 轻量LLM] NPC 短时意图
  ├── [P6 轻量LLM] 传言扩散
  └── [P7 叙事LLM] 场景快照（时间跨度≥阈值时）

location_changed event（玩家切换地点）
  ├── [P1 确定性] 新地点 NPC 状态生成
  ├── [P2 轻量LLM] 新地点 NPC 意图初始化
  └── [P3 轻量LLM] 传言扩散（新地点相关）

chat_turns event（每 N 轮对话）
  ├── [P1 确定性] 关系值衰减
  ├── [P2 轻量LLM] 关系微调
  └── [P3 叙事LLM] 世界背景推进
```

## 输出方式

Agent 输出的处理方式分为三种：

1. **静默 patch**：直接合并到游戏变量，不显示给玩家。AI 在后续回复中通过 `{{FEMALE_STRANGER}}` 等宏自然读取
2. **系统消息**：作为 `role: 'system'` 消息插入聊天记录末尾（不超过一条），玩家可见但不打断阅读
3. **UI通知**：右下角 toast，如 `"世界时间推进了3小时，张三去了市集"`

不同类型 Agent 建议的输出方式：

| Agent | 推荐输出 |
|-------|----------|
| 生理 tick | 静默 patch |
| NPC 位置巡游 | 静默 patch |
| 关系值衰减 | 静默 patch |
| NPC 短时意图 | 静默 patch + 偶尔系统消息 |
| 关系微调 | 静默 patch |
| 传言扩散 | 静默 patch |
| 场景快照 | 系统消息（摘要插入聊天） |
| 人物成长 | 静默 patch + UI通知 |
| 世界事件 | 系统消息 + UI通知 |

## 待决定

1. **Agent 在对话间隙运行还是独立运行？**
   - 间隙运行：玩家发完消息 → AI 回复 → 检测触发条件 → 跑 agent。简单，无竞态
   - 独立运行：后台定时器，玩家发呆时世界也在推进。但需要处理并发写入

2. **叙事 Agent 输出是否作为系统消息插入聊天？**
   - 是：玩家能直接感知世界变化，但可能打断阅读
   - 否：AI 自然引用的沉浸感更好，但玩家可能注意不到关键变化

3. **NPC 自主行为是否需要 LLM？**
   - 简单巡游/状态机 = 无 API 开销
   - 复杂决策 = 需要 LLM，但效果好很多
