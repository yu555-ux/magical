# 通知系统可扩展方向

## 当前实现回顾

```
事件源                    展示层
──────                    ──────
useGameEventMonitor  →  pushStatus()  →  StatusBell (铃铛面板)
(3s轮询好感度变化)        全局函数        ├─ 📡 终端频道 (系统错误)
                                         │   └─ 未读数 + 红色脉冲
                                         └─ 📜 日志频道 (剧情事件)
                                             └─ 未读数 + 全部已读

addNotification()    →  pushStatus()  +  addToast()
(ChatPage错误/警告)      铃铛存储         右上角浮动3秒
```

### 当前已实现的事件

| 事件 | 检测方式 | 频道 |
|------|---------|------|
| 女性角色好感度 +N | IndexedDB diff | 日志 |
| 好感阶段跨越阈值 | IndexedDB diff | 日志 |
| ChatPage API 错误 | `addNotification()` | 终端 |

## 扩展方向

### 方向 1: 新增游戏事件类型

在 `useGameEventMonitor.ts` 的 diff 逻辑中增加检测：

| 新事件 | 检测方式 | 数据路径 | 类型 | 优先级 |
|--------|---------|---------|------|--------|
| **堕落值变化** | 女性角色堕落值跨越阶段 | `主要人物.女性-*.堕落值` | `warning` | 高 |
| **新物品获得** | `持有物品` 列表新增 key | `主角.持有物品.*` | `success` | 高 |
| **物品丢失** | `持有物品` 列表减少 key | `主角.持有物品.*` | `warning` | 中 |
| **地图异常具现** | 任意地点异常 `具现进度 ≥ 100%` | `地图.*.地点细节.异常.*.具现进度` | `error` | 高 |
| **异常进度变化** | 任意异常具现进度跨越 50%/75% 阈值 | 同上 | `warning` | 中 |
| **评级提升** | `主角.评级` 字符串变化 | `主角.评级` | `success` | 中 |
| **状态效果新增** | `主角.状态` 新增 key | `主角.状态.*` | `warning` | 中 |
| **状态效果消除** | `主角.状态` key 消失 | `主角.状态.*` | `info` | 低 |
| **梦境倒计时警告** | 离开梦境倒计时 ≤ 5分钟 | `世界.梦境存档.时间` + 锚点 | `warning` | 高 |
| **柳三娘店铺开启** | `checkShopAvailability()` 结果由 false→true | `checkShopAvailability(vars)` | `success` | 中 |
| **资源大幅变化** | 金钱/尸气/蝶烬 跨越阈值 | `主角.资源.*` | `info` | 低 |
| **新 NPC 出现** | `主要人物` 新增角色 | `主要人物.*.*` | `info` | 低 |
| **NPC 位置变更** | `主要人物.*.*.当前位置` 变化 | `主要人物.*.*.当前位置` | `info` | 低 |
| **技能熟练度突破** | `主角.技能.*.熟练度` 从 <100 到 ≥100 | `主角.技能.*.熟练度` | `success` | 低 |

**实现方式**：在 `useGameEventMonitor.ts` 中扩展 `collectFemaleChars` 的等价逻辑到其他数据路径，拉取快照、diff、推送。

### 方向 2: 通知分级与用户偏好

当前所有通知一视同仁。可以引入**重要性分级**和**用户可控的过滤**：

```
重要性：
  P0 (紧急) — Toast + 铃铛红色 + 声音/震动 + 自动展开面板
  P1 (重要) — Toast + 铃铛未读计数
  P2 (普通) — 仅铃铛未读计数
  P3 (忽略) — 不通知

用户设置：
  [ ] 好感度变化通知
  [ ] 堕落值变化通知
  [ ] 物品获得/丢失通知
  [ ] 异常进度通知
  [ ] 倒计时警告
  [ ] API 错误通知
```

**存储位置**：可加在 `FrontendConfigTab.tsx` 或新建 `NotificationSettingsTab`。

### 方向 3: 通知历史持久化增强

当前已用 localStorage（最多 100 条）。可优化：

| 当前 | 可升级 |
|------|--------|
| localStorage（同步，5MB 上限） | IndexedDB（异步，无容量限制） |
| 简单数组存储 | 按日期/频道索引 |
| 手动清空 | 自动淘汰策略（30 天过期 / 超过 200 条删旧） |

---

### 方向 4: 通知摘要与智能合并

同类通知可能刷屏（如好感度频繁 +1）。引入**合并窗口**：

```
3秒内同一角色的好感度变化 → 合并为 1 条
  "柳三娘 好感度 +3（12→15）"
  "柳三娘 好感度 +2（15→17）"
  → 合并为 "柳三娘 好感度累计 +5"

同一地点多个异常进度变化 → 合并
  "夏城 异常A 进度 +10%"
  "夏城 异常B 进度 +15%"
  → 合并为 "夏城 2个异常进度推进"
```

**实现**：在 `pushStatus()` 中加一个延迟队列，3 秒窗口内同源事件合并后再写入存储。

---

### 方向 5: 通知联动游戏动作

通知不只是"告知"，更可以附带**快捷操作**：

| 事件 | 快捷操作 | 目标页面 |
|------|---------|---------|
| 好感阶段突破 | 「查看角色」 | ArchivePage → 该角色详情 |
| 地图异常具现 | 「查看地图」 | MapPage → 定位到异常地点 |
| 新物品获得 | 「查看物品」 | WarehousePage |
| 梦境倒计时 | 「返回现实」 | ChatPage 发送预设 prompt |
| 柳三娘店铺 | 「前往店铺」 | ChatPage → 打开 ShopModal |

**实现**：在 `StatusEvent` 接口中新增 `action?: { label: string; handler: () => void }` 字段，通知卡片底部显示操作按钮。

---

### 方向 6: 桌面端通知

在支持的环境下使用浏览器 Notification API：

```typescript
if (Notification.permission === 'granted') {
  new Notification('柳三娘', {
    body: '好感阶段突破：平淡 → 友善',
    icon: '/favicon.ico',
  })
}
```

- 首次请求权限
- P0 级事件推送桌面通知
- 点击桌面通知 → 聚焦浏览器标签页

---

### 方向 7: 通知声音

为重要事件添加音效反馈：

| 事件 | 音效风格 |
|------|---------|
| 好感突破 | 柔和上升音（风铃/水晶） |
| 异常具现 | 低频脉冲（警报） |
| 物品获得 | 短促确认音 |
| API 错误 | 电子噪点 |

**实现**：使用 Web Audio API，预加载短音频文件，在 `pushStatus` 时根据类型触发。

## 实施优先级建议

| 优先级 | 方向 | 理由 |
|--------|------|------|
| **P0** | 方向 1 — 新增核心事件（堕落值、物品、异常、倒计时） | 最直接影响玩家体验，让铃铛"有事可报" |
| **P1** | 方向 5 — 通知联动快捷操作 | 让通知从"被动告知"升级为"主动导航" |
| **P1** | 方向 4 — 智能合并 | 防止刷屏，提升信息密度 |
| **P2** | 方向 2 — 分级与偏好 | 用户可控，减少打扰 |
| **P2** | 方向 3 — IndexedDB 持久化 | 大规模数据场景需要 |
| **P3** | 方向 6/7 — 桌面通知/声音 | 锦上添花，非核心 |
