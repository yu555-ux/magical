# Agent 玩法设计

> Agent = 独立 AI 调用，有专属 system prompt，输入结构化数据，输出结构化结果（JSON）。与主 AI（叙事）分离，按需触发。

---

## 一、Agent 与主 AI 的区别

| | 主 AI（叙事） | Agent |
|---|---|---|
| 职责 | 写故事、扮演角色 | 做特定判断或计算 |
| 输出 | 自然语言 + XML 标签 | JSON 或其他结构化数据 |
| 调用时机 | 每次玩家输入 | 按需触发（战斗、调查、遭遇等） |
| 模型 | 需要强写作能力 | 可用更小更快的模型 |
| 上下文 | 长篇对话历史 | 只需当前状态片段 |

---

## 二、Agent 列表

### 优先级 1

#### 2.1 NPC 自主行为 Agent

让世界"活"起来，不依赖玩家驱动。定时或按条件触发。

**输入**：所有 NPC 的位置 / 状态 / 当前行动 / 性格

**输出**：每个 NPC 的下一步行动

```
输入: {
  npcs: [
    { name: "张云", 位置: "11号楼-601室", 当前行动: "在饭桌上吃饭", 状态: "平静" },
    { name: "顾昀", 位置: "11号楼-602室", 当前行动: "研究魔法", 状态: "焦虑" },
    { name: "柳三娘", 位置: "幸福小区-301室", 当前行动: "抽烟", 状态: "无聊" }
  ]
}
输出: {
  张云:   { 行动: "收拾碗筷去厨房", 优先级: "低" },
  顾昀:   { 行动: "发现魔法书缺页，决定去夏城师范大学图书馆", 优先级: "高", 触发事件: true },
  柳三娘: { 行动: "下楼去地下车库取药材", 优先级: "中" }
}
```

高优先级 + 触发事件的行动可自动推动剧情。

#### 2.2 战斗裁决 Agent

代码做裁判，AI 做说书人。独立裁决战斗，输出纯数值。

**输入**：双方状态 + 玩家行动意图 + 战斗规则

**输出**：双方行动 + 伤害 + 消耗 + 状态变化

```
输入: {
  player:  { 评级:"微尘", 生命:100, 能量:80, 力量:10, 技能:["基础魔法"] },
  enemy:   { 评级:"凝石", 生命:300, 体质:20, 技能:["暗影触手","恐惧尖啸"] },
  action:  "用魔力弹幕压制，保持距离",
  rules:   "伤害 = 力量 × 评级系数 × 技能倍率 - 体质 × 0.5"
}
输出: {
  player_action:    { type: "skill", name: "魔力弹幕" },
  enemy_action:     { type: "attack", name: "暗影触手" },
  player_damage:    8,
  enemy_damage:     19,
  player_cost:      20,
  status_effects:   [],
  tactical_note:    "伤害不足以阻止敌人，它正在逼近"
}
```

代码验证合规 → 更新变量 → 主 AI 收到结果，叙写整个过程。

#### 2.3 遭遇 / 事件生成 Agent

基于时间 + 位置 + 概率生成随机事件种子。只给种子，不给完整叙事。

**输入**：地点 / 时间 / SAN / 剧情阶段

**输出**：事件类型 + 种子叙述

```
输入: { 地点: "幸福小区-地下车库", 时间: "02:00", SAN: 65 }
输出: {
  类型: "听觉异常",
  强度: "轻微",
  种子: "车库深处传来有节奏的金属敲击声，像有人在修车——但现在是凌晨2点",
  SAN消耗: 2
}
```

主 AI 拿到种子后展开叙事，决定是否进一步触发检定或战斗。

### 优先级 2

#### 2.4 CoC 风格检定 Agent

通用判定机制。遇到需要运气 / 属性的场合——撬锁、潜行、精神抵抗——统一用属性 + 评级 + 随机值判定。

**输入**：检定类型 / 角色属性 / 难度

**输出**：成功/失败 + 程度 + 后果

```
输入: { 类型: "精神抵抗", 精神: 10, 难度: "凝石", SAN: 65 }
输出: {
  结果: "失败",
  程度: "轻微",
  SAN扣除: 5,
  提示: "你感到一股冰冷的存在正试图钻进你的意识，头皮发麻"
}
```

#### 2.5 线索 / 调查判定 Agent

玩家调查某个地点或异常时，判定发现了什么。

**输入**：调查目标 / 角色技能 / SAN / 已有线索

**输出**：发现内容 + SAN 消耗 + 调查深度

```
输入: { 目标: "601室镜子", 技能: "梦境行走(聚砂)", SAN: 45, 已发现: ["镜中倒影延迟"] }
输出: {
  发现: "倒影的嘴唇在无声地念一个名字——'珈尔'",
  SAN消耗: 3,
  调查深度: 2/5,
  新线索: true
}
```

#### 2.6 梦境生成 Agent

玩家进入梦境时，根据现实地点和当前剧情生成梦境场景要素。

**输入**：现实地点数据 / 剧情进度 / SAN / 已探索梦境

**输出**：梦境扭曲 / 异常 / 可探索点

```
输入: { 地点: "11号楼", 进度: "第三章", SAN: 72 }
输出: {
  梦境扭曲: "楼道无限延伸，每扇门后都通向同一个房间",
  梦境异常: "走廊尽头的镜子里站着一个不是你的人",
  可探索点: ["镜子", "202室门缝透出的光", "电梯按钮上的裂痕"],
  现实原型: "幸福小区最高的住宅楼，共18层"
}
```

### 优先级 3

#### 2.7 谜题状态管理 Agent

追踪线索组合，判定解谜进度。

**输入**：已收集线索 / 当前行动

**输出**：解谜进度 / 解锁内容

```
输入: {
  线索: ["老槐树血瞳", "601室镜子倒影", "柳三娘的药草"],
  行动: "在老槐树下使用蝶烬粉末"
}
输出: { 进度: 3/4, 解锁: "树洞内壁浮现出符文的一部分——它指向地下车库" }
```

#### 2.8 势力 / 关系演变 Agent

不定期触发。根据近期剧情更新 NPC 之间和势力之间的关系。

**输入**：NPC 位置 / 好感值 / 近期剧情摘要

**输出**：关系变化

```
输入: { npcs: [...], 近期事件: ["顾昀在梦境中救了柳三娘"] }
输出: { 变化: { 柳三娘→顾昀: "态度由'漠不关心'转为'暗中观察'" } }
```

#### 2.9 节奏控制 Agent

监控全局节奏——太久没战斗？太久没日常？安静太久需要打破？

**输入**：最近的剧情类型序列（日常/探索/战斗/社交）+ 时间戳

**输出**：节奏建议

```
输入: { 最近类型: ["日常","日常","日常","社交"], 持续时间: "游戏内3小时" }
输出: { 建议: "引入意外事件打破平静", 倾向: "轻度异常" }
```

#### 2.10 伏笔追踪 Agent

记录主 AI 埋下的伏笔，在合适时机提醒回收。

**输入**：所有伏笔记录 + 当前剧情位置

**输出**：可回收伏笔 + 回收建议

```
输入: { 伏笔: [{ id:1, 内容:"珈尔的身份尚未揭示", 章节:1 }], 当前章节: 4 }
输出: { 可回收: [{ id:1, 建议:"顺理成章的时机——珈尔已出场数次" }] }
```

## 三、架构

```
玩家输入 → assemblePrompt
              ├── 检查触发条件（是否进入战斗/调查/梦境）
              ├── 按需调用 Agent（独立 API，低延迟模型）
              │     ├── 战斗 Agent
              │     ├── 检定 Agent
              │     ├── 遭遇 Agent
              │     └── ...
              ├── Agent 结果注入 prompt
              └── 主 AI 叙事
         → API 调用 → 流式解析 → vars 合并 → 持久化
```

## 四、Agent 触发条件总览

| Agent | 触发条件 |
|-------|---------|
| NPC 自主行为 | 每 N 轮对话 / 玩家休眠 / 时间推进 |
| 战斗裁决 | 玩家对敌人使用技能或攻击 |
| 遭遇/事件 | 移动到新地点 / 时间流逝 / 概率触发 |
| CoC 检定 | 高风险行动 / 精神污染 / 环境威胁 |
| 线索调查 | 玩家检查特定对象或地点 |
| 梦境生成 | 每次进入梦境 |
| 谜题管理 | 收集到新线索时 |
| 关系演变 | 每章结束 / 重大事件后 |
| 节奏控制 | 每 N 轮对话 |
| 伏笔追踪 | 每章结束 / 引入新伏笔时 |

## 五、异步 Agent

### 5.1 同步 vs 异步

| | 同步 Agent | 异步 Agent |
|---|---|---|
| 触发方式 | 玩家输入时被动响应 | 时间 / 状态变化 / 定时器自动触发 |
| 等待 | 玩家等结果 | 后台静默运行 |
| 结果 | 即时注入当前 prompt | 写入变量，下次对话生效 |
| 感知 | 玩家看到即时反馈 | 世界"自己变了"，玩家发现而非被告知 |

### 5.2 核心价值

**世界在玩家不在场时也在运转。** 同步让玩家推动世界，异步让世界推动玩家。

### 5.3 异步 Agent 类型

#### NPC 独立生活线

NPC 有自己的时间表，不依赖玩家互动。

```
每游戏内 30 分钟触发:
  扫描所有 NPC 位置/状态
  → 张云: 20:00 客厅 → 20:30 出门去超市
  → 顾昀: 持续研究魔法 → 21:00 检测到异常波动，出门查看
  → 周安: 19:00 从江城出发 → 22:00 到家

结果: 静默写入 NPC 当前位置/当前行动
```

玩家 22:30 回到家，发现周安已经坐在客厅——不是 AI 编的，是后台算好的。

#### 异常自主进化

异常不等人调查，有自己的生长节奏。

```
每游戏日午夜触发:
  扫描所有地图节点异常
  → 血伞: 37% → 42%（日均+5%）
  → 血瞳: 12% → 18%
  → 血伞进度 > 40% → 解锁新效果 "楼道中行走有概率被红伞跟随"

结果: 写入 地图.*.地点细节.异常.*.具现进度
```

玩家拖延不调查 → 异常恶化 → 下次 `{{MAP}}` 自动反映给 AI。

#### 双世界渗透

现实与梦境互相渗透，差值越大渗透越强。

```
每游戏内 1 小时触发:
  对比同一节点的现实与梦境异常
  → 11号楼: 现实血伞 42%, 梦境血伞 68%，差值 26%
  → 渗透事件: "现实中601室的镜子偶尔映出梦境倒影"
  → 写入 主角.状态.现实渗透

结果: 下次对话自动注入提示词
```

#### 世界新闻流

重要事件不靠玩家碰巧发现，主动通知。

```
异步 Agent 检测到事件（周安回家 / 血伞突破阈值 / 顾昀出门）:
  → 判断重要性 > 阈值
  → 推送通知: "你听到楼下传来关门声——周安回来了？"
  → 或存入"未读事件"队列，闲时查看
```

#### 预生成缓存

不等到需要才计算，提前算好。

```
玩家在幸福小区:
  → 异步预计算: 地下车库/浅阳湖/中心广场 的遭遇
  → 缓存结果

玩家走进地下车库:
  → 遭遇瞬间触发（读缓存），零延迟
```

### 5.4 触发机制

| 机制 | 适用 Agent |
|------|-----------|
| **定时触发**（游戏时钟） | NPC 行为、异常进化、双世界渗透 |
| **事件触发**（状态变化） | SAN 暴跌→疯狂、评级突破→觉醒、NPC 死亡→世界反应 |
| **位置触发**（预生成） | 遭遇缓存、对话种子 |

### 5.5 架构

```
                     ┌── 主流程（同步）──┐
玩家输入 → 过滤 → 组装 → 主AI → 渲染
                │
                ├── 并行调用 ── 战斗Agent（同步等待）
                │
                └── 后台队列（异步）──┐
                         │
              ┌──────────┴──────────┐
              │  定时触发（游戏时钟）│
              │  · NPC行为           │
              │  · 异常进化          │
              │  · 双世界渗透        │
              ├──────────────────────┤
              │  事件触发（状态变化）│
              │  · SAN暴跌 → 疯狂    │
              │  · 评级突破 → 觉醒   │
              │  · NPC死亡 → 世界反应│
              ├──────────────────────┤
              │  预生成（位置变化）  │
              │  · 遭遇缓存          │
              │  · 对话种子          │
              └──────────────────────┘
                         │
                         ↓
              结果静默写入变量 / 通知队列
                         │
                         ↓
              下次对话自动注入，玩家无感知
```

### 5.6 设计决策

**游戏时钟**：用 `世界.现实.时间` 驱动，不用墙上时钟。

**结果存储**：写入变量树，下次 `assemblePrompt` 自动读取。

```
世界.异步事件: [{ 类型:"NPC回家", 角色:"周安", 时间:"22:00" }]
```

对话开始时注入提示词 → 清空队列。

**玩家感知**：大部分时候不感知——到家灯亮着、茶几上有热茶。重要事件推送通知。

### 5.7 实现优先级

| 顺序 | 功能 | 理由 |
|------|------|------|
| 1 | 定时触发器框架 | 所有异步 Agent 的基础设施 |
| 2 | NPC 自主行为 | 感知最强，"世界活了" |
| 3 | 异常自主进化 | 制造紧迫感，不调查=恶化 |
| 4 | 双世界渗透 | 核心玩法深度 |
| 5 | 通知/事件队列 | 让异步结果可感知 |
| 6 | 预生成缓存 | 性能优化，锦上添花 |
